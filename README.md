# EduGuard AI
## Student Burnout & Dropout Early-Warning System

> **Disclaimer:** This is an educational machine-learning prototype.  
> It does NOT provide medical, clinical, or psychological diagnoses.  
> All outputs are for informational and academic support purposes only.

---

## Problem Statement

Student dropout and burnout are significant challenges in higher education.
Early identification of at-risk students allows institutions to provide
targeted, timely academic support — before a student reaches a critical point.

---

## Project Objectives

1. Analyse academic, behavioral, lifestyle, and psychosocial factors associated with burnout and dropout.
2. Build a machine learning system that predicts both Burnout Level and Dropout Risk.
3. Use a leakage-safe two-stage pipeline: predict burnout first, then use those predictions as features for dropout prediction.
4. Identify the most important contributing factors behind each prediction.
5. Provide a personalised student risk profile with a risk tier.
6. Suggest responsible, non-clinical recommended actions based on the identified risk factors.

## ML Pipeline Architecture

```
Raw Student Features (22 columns)
          |
          v
+-------------------------------+
|  Stage 1: Burnout Prediction  |
|  Random Forest (5-fold OOF)   |
|  -> Low / Medium / High       |
+---------------+---------------+
                |
    Out-of-fold burnout probabilities
    [P_Low, P_Medium, P_High]
    (leakage-safe: each row predicted
     by a model never trained on it)
                |
                v
+-------------------------------+
|  Stage 2: Dropout Prediction  |
|  Stacked Random Forest        |
|  Features = base + burnout    |
|  -> No / Yes + probability    |
+---------------+---------------+
                |
                v
+-------------------------------+
|  Risk Profile Output          |
|  * Burnout Level              |
|  * Dropout Probability        |
|  * Risk Tier (LOW/MED/HIGH/   |
|    CRITICAL)                  |
|  * Key Risk Factors           |
|  * Recommended Actions        |
+-------------------------------+
```

### Why Out-of-Fold (OOF) Stacking?

Using the observed `Burnout_Level` label directly as a dropout model feature
introduces **target-derived leakage** — at inference time, the true burnout
label is not available. The OOF approach ensures:

- Burnout probabilities on training rows are **never generated by a model that saw those rows**.
- A **baseline Dropout model** (no burnout features) is trained for honest comparison.
- At inference time, burnout probabilities are always predicted — mirroring training exactly.

---

## How to Run

```bash
python app.py
```

The application will:
1. Load and clean the dataset
2. Generate 8 EDA visualizations in `output/plots/`
3. Train the burnout model with 5-fold out-of-fold cross-validation
4. Train and compare baseline vs stacked dropout models
5. Generate model evaluation plots (ROC curves, confusion matrix, feature importance)
6. Profile three demo students (Critical / Medium / Low risk)
7. Save a summary report to `output/summary_report.txt`

**Expected runtime:** approximately 3–5 minutes (due to 5-fold × 5 models for OOF generation).

## Limitations

- Dataset is synthetic — real performance may differ on live data.
- 800 records is a small sample for robust generalisation.
- Cross-sectional snapshot: longitudinal tracking would improve early-warning accuracy.
- No external validation on real student populations.
